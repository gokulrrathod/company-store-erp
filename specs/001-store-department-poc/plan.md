# Implementation Plan: Store Department POC

**Branch**: `001-store-department-poc` | **Date**: 2026-08-20 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-store-department-poc/spec.md`

**Note**: This plan documents an already-built and running system (retrofit), not a forward plan for unwritten
code. It exists so the architecture is reviewable independent of chat history.

## Summary

A React + MUI frontend and a Node/Express + PostgreSQL backend, Dockerized as four services (postgres, pgadmin,
backend, frontend), implementing 8 of the 13 modules in the Store Department SOP with real authentication,
role-based authorization, and transactional inventory updates. Validated end-to-end with Playwright against real
Chrome.

## Technical Context

**Language/Version**: Node.js 20 (backend, ES modules), JavaScript/JSX (frontend, no TypeScript in this POC)

**Primary Dependencies**: Express, `pg`, `bcryptjs`, `jsonwebtoken` (backend); React 18, MUI 5, React Router 6,
Axios, Vite (frontend); `@playwright/test` (e2e)

**Storage**: PostgreSQL 16, 13 tables (see `db/schema.sql`), init-scripted via Docker volume mounts

**Testing**: Playwright, run against the Dockerized stack at `http://localhost:8081`; real Chrome channel used for
recorded demo runs, default Chromium for CI-style runs

**Target Platform**: Docker Compose on the developer's machine (Windows host confirmed working); no cloud
deployment configured yet

**Project Type**: Web application (frontend + backend + database, three-tier)

**Performance Goals**: Not benchmarked — POC scope, single concurrent demo user assumed

**Constraints**: No third-party CDN dependencies in production pages (system font stack only); role checks must be
server-side; every mutating workflow must be transactional

**Scale/Scope**: 8 of 13 SOP modules implemented (GRN/Inspection, Storage fields, Material Issue, Inventory+
Valuation, Rejected Material, Housekeeping, Safety, Dashboard); ~8 seed items, 6 seed users, 2 seed suppliers

## Constitution Check

*Checked against `.specify/memory/constitution.md`.*

- **I. SOP Traceability** — PASS. Spec.md's Assumptions section and the project's gap analysis (in conversation
  history) explicitly list which fields are SOP-sourced vs. extensions (`unit_rate`, `severity`, `zone`).
- **II. Server-Side Role Enforcement** — PASS. Every write route (`purchaseOrders.js`, `materialReceipts.js`,
  `materialRequests.js`, `rejectedMaterials.js`, `housekeeping.js`, `safety.js`) uses `requireRole(...)` middleware,
  not just frontend conditional rendering.
- **III. Atomic Inventory Workflows** — PASS. GRN approval and requisition approval both use `BEGIN`/`COMMIT`/
  `ROLLBACK` with `SELECT ... FOR UPDATE` row locks before mutating `items.quantity`.
- **IV. No Real Personal/Secret Data** — PASS. Seed users are `admin@test.com` etc.; seed suppliers are "Test
  Supplier One/Two"; no real names remain (previously flagged and corrected).
- **V. Test-Covered Modules** — PARTIAL. GRN/Inspection/Approval, Material Requisition/Issue, role-based nav, and
  Low Stock Alerts have Playwright coverage. Rejected Material, Housekeeping, Safety, and Dashboard do **not** yet
  have dedicated test coverage — only manual/screenshot verification. Tracked as a gap in tasks.md.
- **VI. Docker Compose as Source of Truth** — PASS. `docker-compose.yml` mounts `db/schema.sql` and `db/seed.sql`
  as Postgres init scripts; README's manual setup path mirrors it.
